About Forge.

What it is, who has access, why it exists. A short page so visitors landing here can orient themselves without having to ask.

What Forge is

Forge is Hüify's operational brain. A single navigable surface that holds working memory across every system Hüify uses to run: HubSpot for deals and contacts, Drive for documents and contracts, Slack and Gmail for conversations, Gong for calls, Asana for delivery work, and a curated tree of decisions and notes that humans wrote intentionally.

Three thousand-odd nodes captured and indexed. A graph cockpit at /cockpit for spatial navigation. An editorial hub at the root for reading. Markdown lives in the brain tree; visualization lives in the cockpit; both render from the same nodes.

Who has access

The default audience is internal Hüify. The frontmatter on every doc carries a visible_to array. The hub's renderer checks that array against an allowlist before rendering. Anything outside the list (legal, family, health, financial) is excluded from the public render even though the markdown lives in the same tree.

The cockpit is gated separately by password (1835). Same node visibility logic eventually applies there too. For now the password is the rough mechanism.

Why it exists

Hüify runs as a small consultancy with a long memory and a small team. Context is the constraint. When a deal lands or a client asks for something, the right answer is usually distributed across six tools. Reconstructing it by hand each time burns hours that should go elsewhere.

Forge is the attempt to flatten that. Pull every relevant node into one tree, link the related ones, write down the decisions explicitly, and make the whole thing navigable from a single URL. The goal is that anyone (Josh, Erika, Sergio, Ben) can land here and find the current state without having to ping someone.

The federated identity pattern

Same content, different audiences, gated at render time. This page renders on the public hub. The decisions tree renders for internal-Hüify and broader. The work tree renders for internal-Hüify. Anything tagged josh only renders for Josh's own client (or never, on the public hub).

This is not real auth. It is a render-time filter on a static site. The threat model is "casual visitor finds the URL," not "motivated attacker." For higher-sensitivity content, the source repo itself is private and the public deploy renders only what passes the visibility check.

What is in scope

  • HubSpot deals, contacts, companies, notes, calls, emails (extracted)
  • Drive folders and files relevant to active work (extracted)
  • Slack threads and Gmail messages tagged into the brain (extracted)
  • Gong call summaries and transcripts (extracted)
  • Asana tasks and projects (extracted)
  • Curated decisions, threads, people, projects, playbooks (handwritten)

What is not in scope

  • Real-time chat (use Slack)
  • Money movement (PayPal, invoicing). Anything financial stops at "surface for review."
  • Legal counsel. Forge can flag, draft, and reference but it does not give legal advice.
  • HR or employment decisions for Hüify. Same rule.

Build context

The Phase 2 deploy script consolidates the six extraction outputs into the hub repo before pushing to gh-pages.
